Before you start

This spends real money. One monthly membership at the catalog price, $12.99, on your own card, refunded in full at the end. Stripe keeps its processing fee on the charge; the rest comes back to the card within a few days.

Only the owner runs it, and only once. An agent may build or read this page, never click through it.

If a step doesn't match, stop there. Don't edit the row, don't resend webhook events, don't "fix" it in the admin. Read the endpoint's deliveries, then see "If something doesn't match" below.

Reading the state

Two places, after every step

  1. The row. Neon console → the production branch → SQL Editor. Read-only: 
    select subscription_status, paid_through_at, dunning_grace_until, cancel_at_period_end,
       billing_interval, subscription_paused, stripe_customer_id, stripe_subscription_id
from visitor_profiles where email = 'your email';
  2. /api/me. On any www.questurian.com page, signed in: DevTools → Console, then 
    fetch('https://api.questurian.com/api/me', {credentials: 'include'}).then(r => r.json()).then(m => console.log(m.principal?.membership))
    Opening the address in a tab does not work: the API refuses a cookie without the site's Origin (403 "Origin not allowed."). The site's own call is in DevTools → Network as well.

Before the card comes out

The purchase

Purchase → cancel → reactivate → cancel → refund

In this order. Each step says what to do, then what the row, /api/me, Stripe and your inbox should show once it lands (a few seconds; up to a minute for the refund).

Never

What this page never does

  • No dispute. Not even to "test" it. A dispute costs a fee whatever the outcome, counts against the account, and cannot be withdrawn. The dispute path is proven in the sandbox.
  • No second card and no second purchase. A decline is read, not retried with another card. Subscribe again after the refund would open a new Checkout page; close it.
  • No test mode as evidence. Test mode has its own products, prices and customers. A result there says nothing about this account. Never the Mac's stripe CLI key.
  • No load on checkout. No scripts, no repeated clicks, no load test against any payment route.
  • No partial refund in place of the full one. It is ignored on purpose, so it proves nothing and leaves a charge behind.
  • Not on the laptop members' accounts. The two $0.50 subscriptions are cutover step 15's decision, not this test.
If something doesn't match

Where to look

  1. Deliveries first. Stripe → Webhooks → the api.questurian.com endpoint. A red delivery names the status the API answered. 400: the signing secret on Railway is not this endpoint's. 403: the request skipped Cloudflare's origin header (the endpoint URL must be https://api.questurian.com/api/payments/webhooks/stripe). 500: read the API log and Sentry for that request id.
  2. Access still on a minute after the refund, with charge.refunded delivered 200: the refund was partial, or it landed on a charge that is not the membership's. Check the amount first.
  3. Access gone, subscription still active in Stripe: the cancel after the refund failed. Cancel it by hand in the Dashboard now so the card is not charged next month, then open an issue with the API log for that delivery.
  4. Anything else: the reconcile dry run lists the disagreement. Stop, and open an issue with the step, the row, /api/me and the delivery log.
