The second is measurably less metronomic, and that is the single thing this

## The lesson that repeated all session

**Seven failures between the brief and the dossier, and the model's content was
right every single time.** A duplicated string, an empty list beside a field
naming the answer, a plan under the key `questions` instead of `requirements`,
an invented source vocabulary, a timestamp where a date belonged, forty-nine
sources with a publisher and no URL.

Each one threw away work already paid for, over a shape. A schema exists so the
model knows what to send, not so the parser can reject what arrived. When a
stage fails, **read the recorded payload before theorising**:

```
sqlite3 apps/ai-blog-writer/data/pipeline.db \
  "select json_extract(data,'\$.data.reason') from stages \
   where stage='stage_v4_research' order by rowid desc limit 1;"
```

Every stage records what it choked on now, and
`apps/backend/scripts/replay_dossier.py` pushes a recorded failure back through
the real normaliser and the real contract offline, in a second, for nothing.
That tool exists because three runs were spent diagnosing one field at a time.

## The bug that made everything else look broken

Every route was `async def` doing blocking work, so **the whole server froze for
the length of a research pass**. It presented as three unrelated faults: a
status pill stuck on "checking", dead links, and the page forgetting which run
it was on. Hours went into treating them separately.

Fixed in `ebb744c2`, verified against the live server, and pinned by a test that
walks every handler in the four blocking routers. **If you add a route here, it
is `def`, not `async def`.**

## Working with this owner

- Plain language and a recommendation. Lead with the answer.
- **Do not stop to ask permission you already have.** "Make the plan to build
  everything we talked about" means plan it *and build it*. This cost a round
  trip.
- **Never edit a backend file while a run is in flight.** `uvicorn --reload`
  restarts on save and kills it. This happened once, mid-grill, and it was
  entirely avoidable — check `runs.status` first.
- They will spot things a model cannot: Moravia Tours was correct in every word
  and was a business winding down (last post 2024, janky checkout). That
  observation produced the liveness check. **Take their editorial reads
  seriously; they are usually right and usually specific.**
- Tell them when something is half-done. They respond well to "here is the half
  I did" and badly to discovering it later.
- Timestamp any run you mention. They run many and need to know which.

## Repo gotchas that cost real time

- **Tests redirect `DATA_DIR` to a temp folder.** Anything checking live state
  through the app inside pytest reads an empty database. Query
  `data/pipeline.db` directly instead. This produced one confidently wrong
  answer this session.
- **The real database is `apps/ai-blog-writer/data/pipeline.db`** (44 runs).
- **Adding a name to `packages/utils` breaks the suite** — tests install a
  process-global stub. New helpers go in `app/shared/`.
- **`require_non_empty` does nothing on the Gemini path.** That translator keeps
  only `type, description, enum, format, nullable, properties, required, items`,
  so `minLength` is dropped and `required` means "key present" again. Use `enum`
  where the constraint is a vocabulary, and say the rest in the prompt.
- **CI runs all five checks**, from `apps/ai-blog-writer`:
  ```
  .venv/bin/python -m pytest apps/backend/tests -q -p no:warnings
  npx vitest run --config apps/frontend/vite.config.ts
  npx tsc --noEmit -p apps/frontend/tsconfig.json
  ./node_modules/.bin/eslint apps/frontend/src --ext .ts,.tsx
  node apps/frontend/scripts/check-boundaries.cjs
  ```
  Check `select count(*) from runs;` before and after a suite run.

## The design conversation, which is a separate thread

Late in the session the owner and the agent worked out where this goes next.
**None of it is built.** It is recorded in full in issue #449; the short version:

**One grill, three modes.** The seed and the grill are shared. What differs is
what they feed:

```
                    ┌─→ Article Brief ─────→ the article graph
seed → grill ───────┼─→ Article Brief ─────→ the article graph (listicle form)
                    └─→ Generation Brief ──→ itineraries_pipeline (already exists)
```

The owner first wanted three carbon copies of the whole pipeline, and was
talked out of it — not on "don't repeat yourself", which they correctly pointed
out is contested and irrelevant at fifty users, but because **every bug found
this session lived in the shared substrate**. Three copies turn eleven open
issues into thirty-three.

Then they were right about something the agent had wrong: an itinerary is not a
longer article. It is structured data, queries against Location Manager, an
entity-resolution step, and possibly writes. **`itineraries_pipeline/` already
exists** with `retrieval.py`, `candidate_scoring.py`, `lodging_selection.py`,
`day_shells.py`, `ordering.py`, behind ADRs 0013 to 0021. Nobody has read it
properly yet; that is the honest prerequisite to planning any of it.

The listicle is nearly free — the article graph with a different form file and a
longer length profile, both of which are markdown. The itinerary is the real
project.

**Mode also fills a real hole:** the form cannot currently be chosen. The grill
infers it and the brief writer picks. ADR 0030 removed form-picking because a
model reading a title chose `analysis` three times and produced three failures
— but the operator naming it up front is a different act from a model guessing.

**The line to hold:** branch freely in the mode layer (form, length, grill
questions, screen). Do not let a mode add a stage to or reorder the article
graph. An itinerary having its own pipeline is not a violation of that; it is a
different product on correct rails.

   one loop. The cheapest real win available.

   unblocks prompt caching and the spend display.

   one.
