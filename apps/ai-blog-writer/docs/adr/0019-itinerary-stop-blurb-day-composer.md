# Itinerary stop blurbs get a per-day narrative composer, gated behind the Intro

The itinerary **stop blurbs** were generated by reusing the single-type listicle writer (`listicle_writer.py`, ADR 0003): each `target` is composed in its own isolated call against a `article_context` that is **frozen once** for the whole batch. That shape is correct for a flat top-N listicle, where every blurb is a standalone venue paragraph — but it is wrong for an itinerary, where the reader is walking a *sequence*. No blurb can see any other stop, the day's order, or the daypart, so the writer is structurally incapable of the connective tissue an itinerary needs ("after the Alcázar, stroll down to lunch at…"). It produces N standalone paragraphs that happen to sit in day order.

We decided to **build a new itinerary stop-blurb composer as its own editor-assist node**, a sibling to the Intro composer (ADR 0018) and `compose_itinerary_brief`. This is the "full sequenced unity loop" ADR 0018 explicitly deferred, scoped down to per-day. The single-type listicle path is **untouched**; only the itinerary blurb path forks off the listicle writer.

Decided shape:

- **Per-day, whole-day call.** One request authors a single day's stop blurbs *as a connected set*, so the model can write intra-day handoffs. Not whole-trip (prompt bloat, loses the thread, serializes everything); the trip-level arc stays the Intro's job.
- **Gated behind the Intro, evaluated per day.** A day is composable only when (1) **Step 2 is locked** (`step2_complete && !step2_in_update_mode`) — locking, not raw intro presence, is the signal the Intro is *finalized*; (2) every stop in the day has a resolved identity; (3) every pooled-category stop has an Angle selected (ADR 0010 preserved; nightlife auto-resolves, key-location/tour-agency exempt). Blocked days surface a reason, mirroring `getItineraryIntroComposeDisabledReason`.
- **Consumes the composed Intro as a framing input** — the ordering dependency is real, not decorative. Inputs: the day's ordered stops (title, category, daypart, `selectionReason`), the composed Intro, `planOverview`, `listTone`, location, title.
- **Thin neighbor context.** Day N's call also receives day N−1's *last* stop and day N+1's *first* stop, read-only, purely for cross-day-boundary handoffs. Each day still writes only its own blurbs and stays independently regenerable.
- **Whole-day regenerate, not gap-fill.** Narrative coherence requires (re)writing the day as a set; you cannot weave transitions around a skipped stop. Days with existing blurbs prompt confirm-before-replace (the `TravelerProfile.composedBrief` pattern). The top-of-Step-3 "write all" pass auto-skips composed-clean days; per-day recompose is explicit.
- **Prose highlights, single field.** Standout facts are woven into the narrative paragraph, not emitted as structured highlight bullets. Output stays the single `blurb` rich-text field and obeys the existing `validate_generated_text` contract (single paragraph, no headings, no em dashes, no leaked process/labels, word-count bound). Zero Payload-schema or ABW→Questura contract change.

## Considered Options

- **Adapt the listicle writer in place** — feed day/daypart/sequence into each existing `target`'s `supportingContext`. Cheapest, but keeps blurbs shackled to a batch whose frozen, per-item context is wrong for sequence-aware prose. ADR 0018 rejected exactly this for the Intro; the distortion compounds with every future change.
- **Per-target batch behind one button ("all at once" = one click, same engine)** — still isolates each blurb; produces no narrative carry-over. This is roughly what `canAutoWriteEmptyFields` already does.
- **Whole-trip single call** — maximal cross-day callbacks, but balloons the prompt, risks the model losing the thread by day 7, and serializes all days into one slow request.
- **Structured highlight bullets** — a separate highlights list per stop. Rejected here: new field on `ItineraryItemBlock` + Payload block, breaks the single-paragraph validator, and forces a formal ABW→Questura LexicalJSON contract that does not yet exist (CONTEXT.md open question). A bullet list is also the opposite of narrative. If rendered highlight chips are ever wanted, that is a separate Questura render project.
- **Gap-fill (skip-existing)** — preserves manual edits but produces broken narrative the moment any stop in the day is already written.

## Consequences

- The Intro becomes a genuine **upstream dependency** of the stop blurbs. Step 2 must be locked before any day is composable. This is the inverse of the old order, where the Intro rode *inside* the blurb batch.
- Regenerating day 1 *after* day 2 is written does **not** retroactively fix day 2's opening handoff (neighbor context is read-only at compose time). Accepted: the Intro carries the real arc; the operator can recompose day 2 if they care.
- The composer is a new **input/orchestration** node, but its **output** is drop-in compatible with the existing Lexical conversion and Payload `blurb` field — the validator is unchanged, so nothing downstream of generation moves.
- Blurbs still gate Step 3 locking (`validateStep3`), unchanged. What changes is *how* they get written, not *that* they are required.
